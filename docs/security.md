# Security

Copia moves whatever you copy, which can include sensitive things. This page describes what it protects against and what it doesn't.

## Design

- **Private network only.** Copia speaks plain HTTP and is meant to run on a private network, ideally [Tailscale](https://tailscale.com), whose WireGuard tunnels encrypt traffic between your devices. Never expose the port to the internet.
- **One shared token.** Every request except `/healthz` must carry the token. It's compared in constant time. The deploy script generates 256 random bits (`openssl rand -hex 32`).
- **Little data at rest.** By default the server keeps one item: each copy replaces the last, and the replaced item is deleted from disk. Desktop clients keep only the current item's received files and clear them at login.
- **Secrets are skipped.** Clients never upload clipboard content that a password manager marks as concealed (`x-kde-passwordManagerHint` on Linux; `org.nspasteboard.ConcealedType`, `TransientType`, `AutoGeneratedType` and 1Password's type on macOS).
- **No third-party code.** The server uses only Go's standard library, the GNOME extension only libraries GNOME ships, the Mac agent only Apple's frameworks. Nothing is fetched from a package registry at build or run time, so there is no dependency supply chain to compromise.
- **Least privilege.** The server runs as an unprivileged systemd *user* service with `NoNewPrivileges` and a private `/tmp`. Its files are created with mode `600`/`700`.
- **Safe file names.** Uploaded file names are reduced to a base name; content is stored as `part-N` files, never under client-chosen names.

## Where the token lives

| Place | File |
|---|---|
| Server | `<install-dir>/copia.env`, `~/copia/copia.env` by default (mode 600) |
| Linux and Mac clients | `~/.config/copia/copia.env` (mode 600) |
| iPhone / iPad | Inside the two shortcuts |
| Temporarily | The signed `.shortcut` files `ios-shortcuts/build.sh` writes to the Mac's Desktop: delete them after importing |

The repository contains no secrets: `copia.env.example` and the shortcut templates hold only placeholders, and `.gitignore` excludes `*.env`.

### Rotating the token

1. On the server, put a new value in `copia.env` in the install directory (`openssl rand -hex 32`) and run `systemctl --user restart copia`.
2. Update `COPIA_TOKEN` in `~/.config/copia/copia.env` on each computer, then log out and back in (Linux) or run `./mac-agent/install.sh` (macOS).
3. Rebuild and re-import the iOS shortcuts.

## What it doesn't protect against

- **Anyone on your network who has the token** can read and replace your clipboard. There is one token, not per-device keys.
- **Anyone who can read the server's disk** can read the current item; it isn't encrypted at rest.
- **Your network:** without Tailscale or similar, traffic on your LAN is unencrypted HTTP.
- **What you copy:** if an app doesn't mark a password as concealed, Copia can't tell it apart from other text. Use *Sync this computer* (Linux) to pause syncing when needed.

## Reporting a problem

Please open an issue on GitHub describing the problem class, without a working exploit.
